# D9 Entry Points — Design (2026-09-11, scoped NOT implemented)

## 0. Motivation (measured, not hypothesized)

- Park 720p30 qp32 P-only warmed t1/t2/t3/t4 = 16.9/21.3/17.0/18.0fps (need 60fps, 3.3x short, scaling 1.2x).
- Component split (park t1): motion 25%, transform 24%, coeff parse 16%, deblock 17%, chroma 12%, headers 5%.
- WAVESTAT (TC_WAVESTAT=1): workers idle 40-60% (wait/work 0.5-1.4, stragglers). Causes: serial v2_parse_ctu for whole frame precedes wavefront; 12x20 grid ramp/drain; nonuniform CTU costs (water-inter stragglers stall diagonals).
- Trial47 verdict: interp memory-bound (NEON 6-tap ≈ scalar per block; tiling worth ~1.3% total). SIMD kernel work futile; D9 must come from VOLUME (fewer nz: RDOQ did, skip would, MVP fix -8% + temporal -2% + chroma -3.5% help) + bandwidth/layout + wavefront stragglers. Parse-side (serial entropy, 16%) remains the one compute-bound candidate. Coeff-parse core already force-inlined; further micro-opts ≈2-3% total.
- Real parse parallelism needs per-row/CTU entry points (FORMAT change, v2.1 batch). Serial 17fps → 60fps needs ~3.5x. No single kernel exceeds ~1.2x. D9 = multi-win program + perf hardware (none on Pi, timings noisy with Dog-native load) for kernel tuning. Do NOT attempt as drive-by trials; schedule dedicated sprint with quiet perf box (this design is the vehicle).
